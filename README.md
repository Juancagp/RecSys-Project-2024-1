## Repository Structure

### `datasets/`

This directory contains the datasets used in the experiments. Each dataset should be placed in its corresponding folder after preprocessing.

### `submodules/`

The repository references the official repositories of the implementations used in this study. The list of submodules can be found in the `.gitmodules` file.

To initialize all submodules locally, run:

```bash
git submodule update --init --recursive
```

### `Preprocess/`

This directory contains the preprocessing scripts for each dataset. If you wish to use a new dataset, add its preprocessing script following the naming convention:

```text
<dataset>_preproc.py
```

### `Train_Test_Best_Models/`

This directory contains the Jupyter notebooks used to run the experiments. Each notebook is named after the implementation evaluated in that experiment.

### `trained_models/`

This directory stores the trained models as well as the CO₂ emission reports generated by CodeCarbon.

For each implementation and dataset, the emission results are stored in `trainingData.json` files. Depending on the notebook, the results may either be saved in a single file containing all experiment details or in dataset-specific subdirectories (see the **Additional Considerations** section for more details).

## Running the Experiments Locally

Before running an experiment, configure the model name, loss function, and dataset to be used. Depending on the notebook, these parameters are either defined at the beginning of the notebook or passed as arguments to the experiment functions.

Once configured, execute the notebook cells sequentially.

Some notebooks generate a `test_script` that must be executed from the command line instead of reporting the evaluation metrics directly. More information can be found in the **Additional Considerations** section.

If you want to evaluate a model or dataset that is not already included in the repository, create a new directory under `trained_models/` following the naming convention:

```text
<model_name>_<loss_function>
```

Inside this directory, create a folder for each dataset and include an empty `trainingData.json` file.

## Submodule Modifications

Future updates to the original implementation repositories may introduce compatibility issues.

In this project, the original **GRU4Rec** implementation could not be used without modifications. Additionally, to make **KerasGRU4Rec** compatible with the current environment, the following changes must be applied to `KerasGRU4Rec/model/gru4rec.py`:

```python
190 ...
191 # gru_layer.reset_states(states=hidden_states)
192 gru_layer.reset_states()
---

235 ...
236 # gru_layer.reset_states(states=hidden_states)
237 gru_layer.reset_states()
```

## Additional Considerations

Since the experiments were conducted in parallel across different Git branches, there are slight differences in the structure of some Jupyter notebooks and their corresponding `trainingData.json` files.

In particular, the experiments can be divided into two groups:

* **Torch-GRU4Rec** and **GRU4Rec-PyTorch**
* **KerasGRU4Rec**, **GRU4Rec-TensorFlow**, and **RecPack**

Despite these differences, the overall workflow is the same for all experiments.

For the first group, all experiment results are stored in a single `trainingData.json` file containing information about the dataset and loss function used.

For the second group, the results are stored separately in dataset-specific directories, with each experiment having its own `trainingData.json` file.
